The Careless Twins

AUTHOR OffScript

We captured communications between two different servers belonging to the same syndicate. They were bragging about their new "military-grade" 2048-bit RSA encryption. We managed to grab both of their public keys and an encrypted message sent to one of them. We suspect their custom prime generator isn't as random as they think.

같은 조직에 속한 서로 다른 두 서버 사이의 통신을 가로챘다. 이들은 새로 도입한 "군용 수준"의 2048비트 RSA 암호화를 자랑하고 있었다. 두 서버의 공개키와 그중 한 서버에 보낸 암호문을 확보했다. 이들이 직접 만든 소수 생성기는 생각만큼 무작위적이지 않은 것 같다.

Write Up

Starting from the Challenge

Two servers use 2048-bit RSA, and the challenge points us toward their custom prime generation. In careless.zip, encryption.py shows how the keys were made, and output.txt provides n1, n2, e, and c1.

1. Finding the repeated prime in encryption.py

The key-generation code creates p once. Server A combines it with q1, and Server B combines the same p with a new q2:

# encryption.py — challenge file (excerpt)
p = getPrime(1024)
q1 = getPrime(1024)
n1 = p * q1

q2 = getPrime(1024)
n2 = p * q2

Q: What does reusing p in both moduli let us calculate?

Both moduli therefore contain the same prime factor. Their greatest common divisor, gcd(n1, n2), gives us p. Applying this to the supplied numbers produces a 1024-bit common factor.

2. From the shared prime to the private key

Dividing n1 by p gives the other prime, q1. With both factors known, we can calculate the private exponent and decrypt c1:

q1 = n1 / p
φ(n1) = (p - 1)(q1 - 1)
d = e⁻¹ mod φ(n1)
m = c1ᵈ mod n1

Here, d is the modular inverse of the public exponent e. The code below reads the integers from output.txt, performs the calculation, and converts the resulting integer back to bytes.

# solve.py — written for this write-up
from math import gcd

values = {}
for line in open("output.txt"):
    if "=" in line:
        name, value = line.split("=", 1)
        values[name.strip()] = int(value)

n1, n2 = values["n1"], values["n2"]
p = gcd(n1, n2)
q1 = n1 // p
d = pow(values["e"], -1, (p - 1) * (q1 - 1))
m = pow(values["c1"], d, n1)
print(m.to_bytes((m.bit_length() + 7) // 8, "big").decode())

The result is the flag below. Encrypting that plaintext again with e and n1 reproduces c1.

문제에서 출발하기

두 서버가 2048비트 RSA를 사용하며, 문제에서는 직접 만든 소수 생성기를 단서로 준다. careless.zip 안의 encryption.py에는 키 생성 과정이 있고, output.txt에는 n1, n2, e, c1이 있다.

1. encryption.py에서 반복된 소수 찾기

키 생성 코드를 보면 p를 한 번 생성한다. 서버 A는 이를 q1과 곱하고, 서버 B는 같은 p를 새로 만든 q2와 곱한다.

# encryption.py — challenge file (excerpt)
p = getPrime(1024)
q1 = getPrime(1024)
n1 = p * q1

q2 = getPrime(1024)
n2 = p * q2

Q: 두 모듈러에서 p를 재사용하면 어떤 값을 계산할 수 있을까?

따라서 두 모듈러에는 같은 소인수가 들어 있다. 최대공약수인 gcd(n1, n2)를 구하면 p가 나온다. 제공된 숫자로 계산했을 때 1024비트 공통 소인수를 얻었다.

2. 공통 소수로 개인키 구하기

n1을 p로 나누면 나머지 소수 q1을 얻는다. 두 소인수를 알았으므로 다음과 같이 개인 지수를 계산하고 c1을 복호화할 수 있다.

q1 = n1 / p
φ(n1) = (p - 1)(q1 - 1)
d = e⁻¹ mod φ(n1)
m = c1ᵈ mod n1

여기서 d는 공개 지수 e의 모듈러 역원이다. 아래 코드는 output.txt의 정수를 읽어 계산한 뒤, 결과 정수를 다시 바이트로 바꾼다.

# solve.py — written for this write-up
from math import gcd

values = {}
for line in open("output.txt"):
    if "=" in line:
        name, value = line.split("=", 1)
        values[name.strip()] = int(value)

n1, n2 = values["n1"], values["n2"]
p = gcd(n1, n2)
q1 = n1 // p
d = pow(values["e"], -1, (p - 1) * (q1 - 1))
m = pow(values["c1"], d, n1)
print(m.to_bytes((m.bit_length() + 7) // 8, "big").decode())
