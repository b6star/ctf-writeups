Known Plaintext PRNG

AUTHOR OffScript

A custom stream-like cipher encrypts a flag in four-byte blocks. Each block is XORed with a 32-bit key, and the key is mutated using a predictable linear congruential generator. The starting key was supposed to be secret, but the flag format reveals the first plaintext block.

직접 만든 스트림 암호 형태의 암호가 플래그를 4바이트 블록으로 암호화한다. 각 블록은 32비트 키와 XOR되며, 키는 예측 가능한 선형 합동 생성기로 갱신된다. 시작 키는 비밀이어야 했지만, 플래그 형식에서 첫 평문 블록을 알 수 있다.

Write Up

Starting from the Challenge

The challenge gives us encrypt.py and flag.enc. The flag is encrypted in four-byte blocks: each block is XORed with a 32-bit key, then a fixed formula updates the key for the next block. The flag format gives us the first four plaintext bytes, InIt.

1. Recovering the initial key from the known prefix

For XOR encryption, C = P XOR K, so C XOR P = K. Applying that relation to the first ciphertext bytes gives:

Ciphertext: d9 7f e1 ea
InIt:       49 6e 49 74
Key:        90 11 a8 9e

Q: Do four known plaintext bytes reveal only part of the state, or the whole state?

Each block and each PRNG state is exactly four bytes. The known InIt prefix fills the entire first block, so the XOR result reveals all 32 bits of the initial state.

The encryption code uses big-endian byte order, so these key bytes represent 0x9011a89e.

2. One state gives us the rest of the keys

The key update is an LCG (Linear Congruential Generator):

state = (state × 1103515245 + 12345) mod 2^32

The constants are public, and each state depends only on the previous state. Starting with the recovered key, we can calculate the key for every later block in order.

3. Decrypting each block

# solve.py — written for this write-up
data = open("flag.enc", "rb").read()
state = int.from_bytes(
    bytes(c ^ p for c, p in zip(data[:4], b"InIt")), "big"
)

plain = bytearray()
for offset in range(0, len(data), 4):
    key = state.to_bytes(4, "big")
    block = data[offset:offset + 4]
    plain.extend(c ^ k for c, k in zip(block, key))
    state = (state * 1103515245 + 12345) & 0xffffffff

print(plain.decode())

The current state is used first, and the update happens after that block. This follows the encryption order. For the last, shorter block, zip uses only as many key bytes as there are ciphertext bytes.

문제에서 출발하기

문제에는 encrypt.py와 flag.enc가 주어진다. 플래그를 4바이트씩 나눠 32비트 키와 XOR하고, 정해진 식으로 다음 블록의 키를 만든다. 플래그 형식을 통해 첫 4바이트가 InIt라는 것을 알 수 있다.

1. 알려진 접두부로 첫 키 복구하기

XOR 암호화에서 C = P XOR K이므로 C XOR P = K다. 이 관계를 첫 암호문 바이트에 적용하면 다음 값이 나온다.

Ciphertext: d9 7f e1 ea
InIt:       49 6e 49 74
Key:        90 11 a8 9e

Q: 알고 있는 평문 네 바이트로 상태의 일부만 알 수 있을까, 전체를 알 수 있을까?

암호문 블록과 PRNG 상태가 모두 정확히 4바이트다. InIt가 첫 블록 전체를 채우므로 XOR 결과로 초기 상태 32비트를 모두 얻는다.

암호화 코드에서 사용하는 big-endian 순서로 읽으면 이 키는 0x9011a89e다.

2. 첫 상태에서 나머지 키 계산하기

키 갱신에는 LCG(Linear Congruential Generator)를 사용한다.

state = (state × 1103515245 + 12345) mod 2^32

식에 쓰이는 상수는 공개돼 있고, 다음 상태는 이전 상태만으로 정해진다. 따라서 복구한 첫 키에서 출발해 뒤에 이어지는 블록의 키도 순서대로 계산할 수 있다.

3. 블록별로 복호화하기

# solve.py — written for this write-up
data = open("flag.enc", "rb").read()
state = int.from_bytes(
    bytes(c ^ p for c, p in zip(data[:4], b"InIt")), "big"
)

plain = bytearray()
for offset in range(0, len(data), 4):
    key = state.to_bytes(4, "big")
    block = data[offset:offset + 4]
    plain.extend(c ^ k for c, k in zip(block, key))
    state = (state * 1103515245 + 12345) & 0xffffffff

print(plain.decode())

현재 상태로 블록을 복호화한 다음 키를 갱신한다. 암호화할 때와 같은 순서다. 마지막 블록이 4바이트보다 짧으면 zip이 암호문 길이만큼의 키 바이트를 사용한다.
