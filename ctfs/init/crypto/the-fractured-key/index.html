The Fractured Key

AUTHOR OffScript

We intercepted a secure communication between two operatives. We managed to get the cipher text and a strange script they were using to generate their keys. It looks like they tried to be clever by hiding the true flag among fakes. The true flag follows the standard InIt{...} format, but don't trust everything you decrypt.

두 요원 사이의 보안 통신을 가로챘다. 암호문과 이들이 키를 생성할 때 쓰던 이상한 스크립트를 확보했다. 진짜 플래그를 가짜들 사이에 숨겨 둔 것 같다. 진짜 플래그는 표준 InIt{...} 형식이지만, 복호화되는 내용을 모두 믿어서는 안 된다.

Write Up

Starting from the Challenge

The provided key_gen.py contains the key-generation and encryption functions, while intercepted.txt contains three lines of ciphertext represented in hexadecimal. I opened key_gen.py first.

1. Checking the key space in key_gen.py

The key-generation function contains the following code.

# key_gen.py — challenge file (excerpt)
seed = random.randint(0, 255)
random.seed(seed)

key = bytearray()
for _ in range(32):
    key.append(random.randint(0, 255))
return bytes(key)

The first line limits the seed to one value from 0 through 255. The code then initializes Python's pseudorandom number generator with that seed and draws 32 bytes.

Q: The AES key is 32 bytes long, so how can we still try every candidate?

Python's random produces the same sequence when initialized with the same seed. The key may be 32 bytes long, but this function can produce only 256 different keys because there are only 256 possible seeds. Recreating the key for each seed covers the entire key space used by the challenge.

# solve.py — written for this write-up (excerpt)
for seed in range(256):
    rng = random.Random(seed)
    key = bytes(rng.randint(0, 255) for _ in range(32))

The loop assigns each value from 0 through 255 to seed. random.Random(seed) creates a separate random-number generator initialized with that seed, and calling the same randint(0, 255) operation 32 times reproduces the original key.

2. The First 16 Bytes Are the IV and the Rest Is Ciphertext

The encryption function stores its result as follows.

# key_gen.py — challenge file (excerpt)
iv = os.urandom(16)
cipher = AES.new(key, AES.MODE_CBC, iv=iv)
return iv + cipher.encrypt(pad(data, AES.block_size))

The return value concatenates the IV(Initialization Vector) and encrypted data. Each line of intercepted.txt can therefore be converted from hexadecimal to bytes and split into the first 16 bytes as the IV and the remainder as the ciphertext. Since the IV is included in the result, it does not need to be guessed separately.

Each line can now be decrypted with the key generated from each seed and that line's IV. Because the original data was padded before encryption, the PKCS#7 padding must also be removed after decryption.

3. Trying the 256 seeds

The code tries every seed from 0 through 255 for each line and prints a result when the padding can be removed, the plaintext is readable ASCII, and it matches the InIt{...} format.

# solve.py — written for this write-up
import random
from pathlib import Path
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

for line_no, line in enumerate(Path("intercepted.txt").read_text().splitlines(), 1):
    if not line.strip():
        continue

    data = bytes.fromhex(line.strip())
    iv, ciphertext = data[:16], data[16:]

    for seed in range(256):
        rng = random.Random(seed)
        key = bytes(rng.randint(0, 255) for _ in range(32))

        try:
            plain = unpad(
                AES.new(key, AES.MODE_CBC, iv=iv).decrypt(ciphertext),
                AES.block_size,
            )
            text = plain.decode("ascii")
        except (ValueError, UnicodeDecodeError):
            continue

        if (
            text.startswith("InIt{")
            and text.endswith("}")
            and all(32 <= ord(ch) <= 126 for ch in text)
        ):
            print(line_no, seed, text)

Even decryption with a wrong key can occasionally produce an ending that happens to satisfy the padding rules. I therefore checked both the text itself and the Flag format. Three results remained.

1 42 InIt{w0w_y0u_f0und_1t_but_1ts_f4k3}
2 201 InIt{ps3ud0_r4nd0m_1s_n0t_r4nd0m_k3y_sp4c3_t00_sm4ll}
3 137 InIt{h4h4_n1c3_try_k33p_l00k1ng}

4. Selecting the Real Answer from the Three Results

The first line identifies itself as a fake with f4k3, while the third says to keep looking with k33p_l00k1ng. Their contents indicate that both strings are decoys.

The second line describes the flaw just exploited: the key space generated by the pseudorandom process is too small. I submitted this value and confirmed it was Correct.

Final Flag

InIt{ps3ud0_r4nd0m_1s_n0t_r4nd0m_k3y_sp4c3_t00_sm4ll}

Summary

  • Key generation: The seed is limited to 0–255, so every candidate key can be reproduced.
  • Data layout: The first 16 bytes of each line are the IV; the rest is AES-CBC ciphertext.
  • Result: Line 2 with seed 201 gives the flag. The other two messages identify themselves as decoys.

문제에서 출발하기

제공된 key_gen.py에는 키 생성과 암호화 함수가 있고, intercepted.txt에는 16진수로 표현된 암호문 세 줄이 있다. 먼저 key_gen.py를 열었다.

1. key_gen.py에서 키 후보 범위 확인하기

키 생성 함수에는 다음 코드가 있다.

# key_gen.py — challenge file (excerpt)
seed = random.randint(0, 255)
random.seed(seed)

key = bytearray()
for _ in range(32):
    key.append(random.randint(0, 255))
return bytes(key)

첫 줄에서 시드를 0부터 255까지로 제한한다. 그다음 random.seed(seed)로 Python의 의사난수 생성기를 초기화하고, 숫자를 32번 뽑아 키를 만든다.

Q: AES 키는 32바이트인데 어떻게 후보를 전부 넣어 볼 수 있을까?

Python의 random은 같은 시드에서 같은 숫자열을 만든다. 키 길이는 32바이트지만 이 함수가 만들 수 있는 키는 시드 수와 같은 256개뿐이다. 시드 0부터 255까지 같은 과정을 반복하면 문제에서 사용한 키 후보 전체를 재현할 수 있다.

# solve.py — written for this write-up (excerpt)
for seed in range(256):
    rng = random.Random(seed)
    key = bytes(rng.randint(0, 255) for _ in range(32))

반복문의 seed에 0부터 255까지 하나씩 지정한다. random.Random(seed)는 해당 시드로 초기화한 별도의 난수 생성기이며, 여기서 원본과 같은 randint(0, 255)를 32번 호출하면 같은 키를 얻는다.

2. 앞 16바이트는 IV, 나머지는 암호문이다

암호화 함수는 다음과 같이 결과를 저장한다.

# key_gen.py — challenge file (excerpt)
iv = os.urandom(16)
cipher = AES.new(key, AES.MODE_CBC, iv=iv)
return iv + cipher.encrypt(pad(data, AES.block_size))

반환값은 IV(Initialization Vector)와 암호화된 데이터를 이어 붙인 바이트열이다. 따라서 intercepted.txt의 각 줄을 16진수에서 바이트로 바꾼 뒤, 앞 16바이트를 IV로, 나머지를 암호문으로 나눈다. IV는 결과에 포함돼 있으므로 별도로 추측할 필요가 없다.

이제 각 시드로 만든 키와 해당 줄의 IV를 사용해 AES-CBC 복호화를 시도하면 된다. 원본은 암호화 전에 패딩을 붙였으므로 복호화한 뒤에는 PKCS#7 패딩도 제거한다.

3. 시드 256개로 복호화하기

다음 코드는 각 줄에 대해 시드 0부터 255까지를 모두 시도하고, 패딩을 제거한 결과가 읽을 수 있는 ASCII 문자열이면서 InIt{...} 형식일 때 출력한다.

# solve.py — written for this write-up
import random
from pathlib import Path
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

for line_no, line in enumerate(Path("intercepted.txt").read_text().splitlines(), 1):
    if not line.strip():
        continue

    data = bytes.fromhex(line.strip())
    iv, ciphertext = data[:16], data[16:]

    for seed in range(256):
        rng = random.Random(seed)
        key = bytes(rng.randint(0, 255) for _ in range(32))

        try:
            plain = unpad(
                AES.new(key, AES.MODE_CBC, iv=iv).decrypt(ciphertext),
                AES.block_size,
            )
            text = plain.decode("ascii")
        except (ValueError, UnicodeDecodeError):
            continue

        if (
            text.startswith("InIt{")
            and text.endswith("}")
            and all(32 <= ord(ch) <= 126 for ch in text)
        ):
            print(line_no, seed, text)

잘못된 키로 복호화해도 끝부분이 우연히 패딩 규칙에 맞을 수 있다. 따라서 문자열의 내용과 플래그 형식을 함께 확인했다. 이렇게 남은 결과는 다음 세 개다.

1 42 InIt{w0w_y0u_f0und_1t_but_1ts_f4k3}
2 201 InIt{ps3ud0_r4nd0m_1s_n0t_r4nd0m_k3y_sp4c3_t00_sm4ll}
3 137 InIt{h4h4_n1c3_try_k33p_l00k1ng}

4. 세 결과 중 실제 정답 고르기

1행은 f4k3로 자신이 가짜라고 밝히고, 3행은 k33p_l00k1ng이라며 계속 찾으라고 한다. 두 문자열은 내용상 미끼로 판단했다.

2행은 의사난수로 만든 키의 후보가 너무 적다는 뜻으로, 방금 이용한 코드의 결함과 맞는다. 이 값을 제출해 Correct를 확인했다.

요약

  • 키 생성: 시드가 0–255라서 후보 키를 모두 재현할 수 있다.
  • 저장 구조: 각 줄의 앞 16바이트는 IV, 나머지는 AES-CBC 암호문이다.
  • 결과: 2행을 시드 201로 복호화해 플래그를 얻는다. 다른 두 메시지는 내용에서 미끼임을 드러낸다.
