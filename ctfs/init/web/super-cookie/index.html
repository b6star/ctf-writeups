Super Cookie

AUTHOR Abdullah Hamdan

A small office story archive with an administrator area that is restricted to authorized staff. The cookie is unsafe somewhere, but can I really get admin access if the cookie is unsafe?

사무실 이야기를 모아 둔 작은 사이트가 있다. 관리자 영역은 권한이 있는 직원만 접근할 수 있다. 쿠키 처리 어딘가에 문제가 있다는데, 그것만으로 정말 관리자 권한을 얻을 수 있을까?

Write Up

Starting from the Challenge

The first page shows only an office story and no login address.

robots.txt is a public file that tells search-engine crawlers which paths to avoid. It can reveal paths missing from the site's navigation, so I opened /robots.txt and found the administrator path:

/admin/8f14e45f-ea9d-4b21-9c6d-62f8f7a6c311

1. Opening the administrator path and inspecting the session

Opening the administrator path for the first time displays a visitor login page. The server issues a session cookie through the response's Set-Cookie header, and the browser stores it automatically. It can be viewed under Application → Cookies in the developer tools, or the response headers can be inspected with the following command.

curl -i 'http://172.198.60.104:3000/admin/8f14e45f-ea9d-4b21-9c6d-62f8f7a6c311'

The cookie payload identified the current user as a visitor.

# Session Payload
{"role":"guest","username":"visitor"}

Q: The role is visible in the cookie, so why not change guest directly to admin?

A Flask session allows its contents to be read, but uses an HMAC(Hash-based Message Authentication Code) signature to detect tampering. Changing only role to admin invalidates the signature, so the server issues another guest cookie. Creating an admin cookie requires the SECRET_KEY the server used to sign it.

2. Recovering the signing key

The guest cookie issued by the server has a valid signature. By generating the same signature with candidate keys and comparing it with the guest cookie's signature, the SECRET_KEY can be tested without sending each candidate to the server.

flask-unsign --unsign --cookie "$SESSION_COOKIE" --wordlist rockyou.txt

Trying the candidates showed that the key matching the valid cookie's signature was secret123.

3. Opening the admin panel with a new cookie

flask-unsign --sign --cookie '{"role":"admin","username":"admin"}' --secret secret123 --no-literal-eval

This signs a session with both role and username set to admin. Replace the browser's session cookie value with the full output of the command, then reload the administrator page.

The page shows Welcome, admin. and Admin panel unlocked., along with the flag.

문제에서 출발하기

첫 화면에는 사무실 이야기만 보이고 로그인 주소는 없다.

robots.txt는 검색 엔진 크롤러에게 접근하지 말아야 할 경로를 알려 주는 공개 파일이다. 사이트 메뉴에 없는 경로가 적혀 있을 수 있어 열어 봤고, 다음 관리자 경로를 찾았다.

/admin/8f14e45f-ea9d-4b21-9c6d-62f8f7a6c311

1. 관리자 경로에서 session 쿠키 확인하기

관리자 경로에 처음 접속하면 방문자 로그인 화면이 나타난다. 이때 서버는 응답의 Set-Cookie 헤더로 session 쿠키를 발급하고 브라우저는 이를 자동으로 저장한다. 개발자 도구의 Application → Cookies에서 확인하거나 다음 명령으로 응답 헤더를 볼 수 있다.

curl -i 'http://172.198.60.104:3000/admin/8f14e45f-ea9d-4b21-9c6d-62f8f7a6c311'

쿠키의 페이로드에는 현재 사용자가 방문자라는 정보가 들어 있었다.

# Session Payload
{"role":"guest","username":"visitor"}

Q: 쿠키에서 role이 보이는데 guest를 admin으로 바로 바꾸면 안 될까?

Flask 세션은 쿠키 안의 내용을 읽을 수 있지만 HMAC(Hash-based Message Authentication Code) 서명으로 변조 여부를 검사한다. role만 admin으로 바꾸면 서명이 맞지 않아 서버가 다시 guest 쿠키를 발급한다. admin 쿠키를 만들려면 서버가 서명에 사용한 SECRET_KEY를 알아내야 한다.

2. 서명 키 찾기

서버가 발급한 guest 쿠키는 서명이 올바른 쿠키다. 후보 키로 같은 서명을 만들어 guest 쿠키의 서명과 비교하면 SECRET_KEY를 서버에 요청하지 않고 검사할 수 있다.

flask-unsign --unsign --cookie "$SESSION_COOKIE" --wordlist rockyou.txt

후보를 대입한 결과 정상 쿠키의 서명과 일치하는 키는 secret123이었다.

3. 새 쿠키로 관리자 페이지 열기

flask-unsign --sign --cookie '{"role":"admin","username":"admin"}' --secret secret123 --no-literal-eval

찾은 키로 role과 username이 모두 admin인 세션을 서명한다. 명령의 출력 전체로 브라우저의 session 쿠키 값을 교체한 뒤 관리자 페이지를 새로 고침한다.

페이지에 Welcome, admin.과 Admin panel unlocked.가 나타나고 플래그가 보인다.

Final Flag

요약

  • 경로 발견: /robots.txt에서 관리자 경로를 찾고 접속해 guest 세션을 받는다.
  • 서명 키: 정상 guest 쿠키의 서명과 후보 키를 비교해 secret123을 찾는다.
  • 접근: admin 세션을 서명하고 그 쿠키로 관리자 페이지를 연다.
