Write Up

Starting from the Challenge

Cash Now has a profile-photo URL field and an ID-image upload form. The supplied source shows two useful paths: the avatar feature fetches a URL on the server, while the document feature creates a thumbnail with ImageMagick and archives it. The Dockerfile places the target at /data/internal/verification_status.txt.

1. Using the avatar URL to find the storage path

The avatar route checks the initial URL's IP address. Its redirect handler blocks 301 and 302, but follows a 307 redirect without checking the new destination. This gives us SSRF (Server-Side Request Forgery).

I set up a public URL that redirects to the local archive service:

HTTP/1.1 307 Temporary Redirect
Location: http://127.0.0.1:39417/archive/config
Content-Length: 0

Q: The original URL passed the IP check, so why does the request still reach localhost?

Entering this URL in the profile-photo field makes the server fetch its own archive configuration. The result is JSON, so the avatar route rejects its content type and includes the beginning of the body in the error shown on the page. That exposes upload_dir, the randomly named upload directory created when the archive service starts.

2. Reading a local file through ImageMagick

The document-upload route uses ImageMagick 7.1.0-48, which is vulnerable to CVE-2022-44268. A PNG tEXt chunk with the key profile can make conversion read a local file and include its contents in the output image's raw profile.

profile\0/data/internal/verification_status.txt

Here, \0 represents a NUL byte separating the keyword from its value. I added this chunk to a PNG so that the thumbnail would contain the verification file.

3. Keeping the thumbnail long enough to download it

The thumbnail is deleted as soon as archiving succeeds. The source also schedules a cleanup after four seconds. To leave that short window open, I uploaded the PNG with a filename whose basename was 300 characters long. Writing the encrypted archive then fails with ENAMETOOLONG and skips the immediate deletion.

The preview endpoint can serve the thumbnail using the storage path found earlier:

/documents/preview?path=<upload_dir>/tmp/<username>.png

I repeatedly requested that preview while uploading the PNG. This captured the 508-byte thumbnail before the scheduled cleanup removed it.

4. Reading the embedded file

The thumbnail contains a zTXt chunk named Raw profile type txt. After decompressing it with zlib, the profile holds the file length followed by hexadecimal data. Converting those hex lines back to bytes gives:

VERIFICATION STATUS: APPROVED
CASE-HI-2026-0917
flag: InIt{ssrf_pNgcrush_3numt00l0ng}

The leaked path connects the two features: the avatar request reveals where to look, and the document thumbnail carries the file we want to read.

Final Flag

InIt{ssrf_pNgcrush_3numt00l0ng}

  • File read: A PNG profile makes ImageMagick embed the verification file in its thumbnail.
  • Retrieval: An overlong filename delays deletion; download the preview and decode its raw profile.

문제에서 출발하기

Cash Now에는 프로필 사진 URL을 입력하는 기능과 신분증 이미지를 업로드하는 기능이 있다. 제공된 소스를 보면 아바타 기능은 서버에서 URL을 요청하고, 문서 기능은 ImageMagick으로 썸네일을 만든 뒤 보관한다. Dockerfile에는 목표 파일이 /data/internal/verification_status.txt에 저장되도록 돼 있다.

1. 아바타 URL로 저장 경로 알아내기

아바타 라우트는 처음 입력한 URL의 IP 주소를 검사한다. 리다이렉트 처리에서는 301과 302를 막지만, 307은 새 목적지를 검사하지 않고 따라간다. 이 부분을 이용하면 SSRF(Server-Side Request Forgery)가 가능하다.

공개 URL이 내부 archive 서비스로 리다이렉트하도록 구성했다.

HTTP/1.1 307 Temporary Redirect
Location: http://127.0.0.1:39417/archive/config
Content-Length: 0

Q: 처음 입력한 URL은 IP 검사를 통과했는데 어떻게 localhost까지 요청이 이어질까?

이 URL을 프로필 사진 입력란에 넣으면 서버가 자신의 archive 설정을 가져온다. 결과가 JSON이므로 아바타 라우트는 콘텐츠 유형 오류를 내면서 본문 앞부분을 페이지의 오류 메시지에 포함한다. 여기서 archive 서비스가 시작할 때 무작위 이름으로 만든 업로드 디렉터리 upload_dir를 얻었다.

2. ImageMagick으로 로컬 파일 읽기

문서 업로드 라우트는 CVE-2022-44268에 취약한 ImageMagick 7.1.0-48을 사용한다. PNG의 tEXt 청크에 profile 키를 넣으면 변환 과정에서 로컬 파일을 읽어 결과 이미지의 raw profile에 포함시킬 수 있다.

profile\0/data/internal/verification_status.txt

여기서 \0은 키와 값을 나누는 NUL 바이트다. PNG에 이 청크를 넣어 썸네일에 검증 파일의 내용이 담기도록 했다.

3. 썸네일이 삭제되기 전에 가져오기

썸네일은 보관에 성공하면 바로 삭제된다. 소스에는 4초 뒤 실행되는 삭제 작업도 있다. 이 짧은 시간 동안 파일이 남게 하려고 확장자를 제외한 이름이 300자인 PNG를 업로드했다. 암호화된 보관 파일을 쓰는 단계에서 ENAMETOOLONG 오류가 발생하면 즉시 삭제하는 코드가 건너뛰어진다.

앞에서 얻은 저장 경로를 사용하면 preview에서 썸네일을 가져올 수 있다.

/documents/preview?path=<upload_dir>/tmp/<username>.png

PNG를 업로드하면서 이 preview 경로를 반복 요청했다. 예약된 삭제가 실행되기 전에 508바이트 썸네일을 확보했다.

4. 이미지에 포함된 파일 읽기

썸네일에는 Raw profile type txt라는 이름의 zTXt 청크가 있다. zlib 압축을 풀면 파일 길이 뒤에 16진수 데이터가 이어진다. 이 16진수 줄들을 바이트로 바꾸면 다음 내용이 나온다.

VERIFICATION STATUS: APPROVED
CASE-HI-2026-0917
flag: InIt{ssrf_pNgcrush_3numt00l0ng}

앞에서 유출한 경로가 두 기능을 연결해 준다. 아바타 요청으로 파일을 찾을 위치를 알아내고, 문서 썸네일에 담긴 목표 파일을 읽는 방식이다.

Final Flag

InIt{ssrf_pNgcrush_3numt00l0ng}

요약

  • 저장 경로: 307 리다이렉트로 내부 archive 설정을 아바타 오류 메시지에 노출시킨다.
  • 파일 읽기: PNG profile을 이용해 ImageMagick 썸네일에 검증 파일을 포함시킨다.
  • 회수: 긴 파일명으로 즉시 삭제를 건너뛴 뒤 preview를 받아 raw profile을 해독한다.

  4. 300자 파일명

  6. raw profile 해독 → 플래그
