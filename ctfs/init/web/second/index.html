Write Up

Starting from the Challenge

LedgerLite lets us create invoices and save reports with a custom sort expression. The report form even says 'Advanced: any ordering expression is accepted,' so I checked where that expression was used in the supplied source.

1. Tracing the saved value into ORDER BY

The form sends the sort expression as sort_key to /reports/new, which saves it in the database. Opening /reports/<report_id>/run later reads that value and inserts it directly into the query:

# routes/reports.py — challenge file (excerpt)
"SELECT id, label, amount, status, created_at FROM invoices "
f"WHERE user_id = {user['id']} ORDER BY {report['sort_key']}"

Q: How can a value stored as ordinary data become SQL later?

The value is stored as data in the first request and used as SQL syntax when the report runs. This is second-order SQL injection. A payload placed in the sort field will be evaluated at the report-execution step.

2. Making the error reveal the flag

The report page displays database errors. MySQL's EXTRACTVALUE includes an invalid XPath expression in its error message, so I used the following sort expression:

EXTRACTVALUE(1,CONCAT(0x7e,(SELECT flag_value FROM flags)))

The subquery reads flags.flag_value. 0x7e adds a leading ~, which makes the resulting XPath invalid and marks the beginning of the leaked value.

3. Saving and running the report

After registering and logging in, I added an invoice. On the report form, I entered a title, pasted the expression into Sort expression, and saved the report. Running the saved report showed this error on the page:

XPATH syntax error: '~InIt{s3c0nd_0rd3r_1nj3ct10n}'

The flag appeared inside the error because the saved sort expression had been evaluated in ORDER BY.

Final Flag

InIt{s3c0nd_0rd3r_1nj3ct10n}

Summary

  • Entry point: The report form saves a custom sort_key.
  • Execution: Running the report inserts that value into ORDER BY.
  • Leak: An invalid XPath makes the report page display the flag in an error.

문제에서 출발하기

LedgerLite에서는 인보이스를 만들고, 정렬식을 지정해 보고서를 저장할 수 있다. 보고서 작성 화면에 'Advanced: any ordering expression is accepted,'라고 적혀 있어, 제공된 소스에서 이 정렬식이 사용되는 부분을 찾아봤다.

1. 저장된 값이 ORDER BY에 들어가는 과정

작성 화면은 정렬식을 sort_key에 담아 /reports/new로 보내고, 서버는 이를 데이터베이스에 저장한다. 이후 /reports/<report_id>/run을 열면 저장된 값을 읽어 쿼리에 그대로 넣는다.

# routes/reports.py — challenge file (excerpt)
"SELECT id, label, amount, status, created_at FROM invoices "
f"WHERE user_id = {user['id']} ORDER BY {report['sort_key']}"

Q: 평범한 데이터로 저장한 값이 어떻게 나중에 SQL이 될까?

첫 요청에서 데이터로 저장한 값이 보고서를 실행할 때 SQL 문법으로 사용된다. 이런 방식을 Second-order SQL Injection이라고 한다. 정렬 필드에 페이로드를 넣어 저장하면 보고서를 실행하는 단계에서 동작한다.

2. 오류 메시지에 플래그가 나오게 만들기

보고서 페이지에는 데이터베이스 오류가 표시된다. MySQL의 EXTRACTVALUE는 잘못된 XPath를 넣으면 오류 메시지에 그 표현식을 포함하므로, 다음 값을 정렬식으로 사용했다.

EXTRACTVALUE(1,CONCAT(0x7e,(SELECT flag_value FROM flags)))

서브쿼리가 flags.flag_value를 읽고, 0x7e가 앞에 ~를 붙인다. 이 값으로 잘못된 XPath를 만들면 오류를 일으키면서 유출된 값의 시작도 쉽게 찾을 수 있다.

3. 보고서를 저장하고 실행하기

계정을 만들고 로그인한 뒤 인보이스를 하나 추가했다. 보고서 작성 화면에서 제목을 입력하고 Sort expression에 위 표현식을 넣어 저장했다. 저장한 보고서를 실행하자 페이지에 다음 오류가 나타났다.

XPATH syntax error: '~InIt{s3c0nd_0rd3r_1nj3ct10n}'

저장된 정렬식이 ORDER BY에서 실행되면서 오류 메시지 안에 플래그가 나왔다.

Final Flag

InIt{s3c0nd_0rd3r_1nj3ct10n}

요약

  • 입력 지점: 보고서 작성 화면이 sort_key를 저장한다.
  • 실행 지점: 보고서를 실행하면 이 값이 ORDER BY에 들어간다.
  • 유출: 잘못된 XPath를 만들어 페이지의 오류 메시지에서 플래그를 읽는다.
