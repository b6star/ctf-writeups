Locked Notes

AUTHOR Kshitij Raj

We pulled the app data from a suspect's Android phone during an investigation. The "Secure Notes" app looked locked on the device, but the data folder came off cleanly. We think they stashed something in there.

Recover the hidden note.

수사 중 용의자의 Android 휴대전화에서 앱 데이터를 추출했다. 기기에서는 "Secure Notes" 앱이 잠겨 있었지만 데이터 폴더는 온전히 확보했다. 그 안에 무언가를 숨겨 둔 것 같다.

숨겨진 메모를 복구하라.

Write Up

Starting from the Challenge

securenotes_data.tar.gz is a backup of a notes app. Extracting it reveals notes.db, logcat, and shared preferences. The challenge says, 'The "Secure Notes" app looked locked on the device, but the data folder came off cleanly.' I first examined which record contained the locked note and what bytes were stored in its body.

1. Matching the log entry to a database row

# logcat.txt
10-11 09:14:11.200  1123  1188 D SecureNotes: opened note _id=4 (locked)

The logcat recorded that locked note _id=4 had been opened. Using this as the target, I queried the SQLite database for its title, lock status, body length, and initial bytes.

SELECT _id, title, is_locked, length(body), hex(substr(body,1,2))
FROM notes
WHERE _id = 4;

# result
4|Recovery Code|1|45|1F8B

Q: Does is_locked = 1 mean the 45-byte body must be decrypted?

In the query result, is_locked=1 is the value the app uses to mark the note as locked. The body begins with the separate value 1F8B, which matches the Gzip signature. The body therefore contains compressed data and can be read by retrieving the binary value and decompressing it with Gzip.

2. Reading the BLOB without corrupting it

A BLOB is a binary value stored inside the database. Converting it to a string first could corrupt the compressed data, so I retrieved it as bytes and passed it to gzip.decompress.

# extract_note.py — written for this write-up
import gzip
import sqlite3

db = sqlite3.connect("notes.db")
row = db.execute(
    "SELECT body FROM notes WHERE _id=? AND is_locked=1",
    (4,),
).fetchone()

if row is None:
    raise SystemExit("locked note not found")

body = row[0]
assert body[:2] == b"\x1f\x8b"
print(gzip.decompress(body).decode())

fetchone() reads the selected record, after which the code confirms the Gzip header and decompresses the data. It converts the result to text with .decode() only after decompression. This produced the complete Flag string.

문제에서 출발하기

securenotes_data.tar.gz는 메모 앱의 백업이다. 압축을 풀면 notes.db, logcat과 shared preferences가 나온다. 문제에는 'The "Secure Notes" app looked locked on the device, but the data folder came off cleanly.'라고 적혀 있다. 먼저 잠긴 메모가 어느 레코드인지와 body가 어떤 바이트인지 조사했다.

1. 로그와 데이터베이스 레코드 연결하기

# logcat.txt
10-11 09:14:11.200  1123  1188 D SecureNotes: opened note _id=4 (locked)

logcat에는 잠긴 메모 _id=4를 열었다는 기록이 있었다. 이를 기준으로 SQLite 데이터베이스를 조회해 제목, 잠금 표시, 내용 길이와 시작 바이트를 함께 확인했다.

SELECT _id, title, is_locked, length(body), hex(substr(body,1,2))
FROM notes
WHERE _id = 4;

# result
4|Recovery Code|1|45|1F8B

Q: is_locked = 1이면 45바이트 body를 복호화해야 할까?

조회 결과에서 is_locked=1은 앱이 메모를 잠금 상태로 표시하는 값이다. body의 시작 바이트는 별도 항목인 1F8B이며 Gzip 시그니처와 일치한다. 따라서 body에는 압축 데이터가 들어 있고, 바이너리 그대로 꺼내 Gzip 압축을 풀면 내용을 읽을 수 있다.

2. BLOB을 손상 없이 읽기

BLOB은 데이터베이스 안의 바이너리 값이다. 이 값을 먼저 문자열로 바꾸면 압축 데이터가 손상될 수 있으므로 bytes 상태로 가져와 gzip.decompress에 전달한다.

# extract_note.py — written for this write-up
import gzip
import sqlite3

db = sqlite3.connect("notes.db")
row = db.execute(
    "SELECT body FROM notes WHERE _id=? AND is_locked=1",
    (4,),
).fetchone()

if row is None:
    raise SystemExit("locked note not found")

body = row[0]
assert body[:2] == b"\x1f\x8b"
print(gzip.decompress(body).decode())

fetchone()으로 선택한 레코드를 읽고, Gzip 헤더가 맞는지 확인한 뒤 압축을 푼다. 압축 해제 후에만 .decode()로 텍스트로 바꾼다. 여기서 완전한 Flag 문자열이 나왔다.
